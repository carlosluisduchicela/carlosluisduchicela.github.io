bonusly · admin os · feb 2026

an admin console runs reports. what would it take for it to run the recognition program itself?

the dashboard today surfaces strong signals: participation, program adoption, and cost. it provides visibility. the question is what its primary job should be.

the short version of the workshop pre-read. the full pre-read and the prototype are linked from the last slide.

01 · the diagnosis

strong signals. no next step.

  • participation & frequency — clear pulse metrics, fast visibility, labels like great / average / low. but a snapshot without interpretation: when an admin sees “average”, what is the intended next step?
  • program adoption — a clear program inventory, transparently configured. but the programs sit as inventory, not levers, with no signal of which one matters most right now.
  • cost — transparent, finance-ready reporting. but it surfaces cost exposure without structured governance guidance, and no clear safe intervention path.

the behavioral guess: admins interpret manually, open support tickets, or leave without action.

02 · the synthesis

visibility without an operating loop

  • strong signal visibility
  • limited prioritization guidance
  • limited decision scaffolding
  • no explicit action → outcome loop

so the dashboard encourages maintenance behavior instead of strategic behavior, and reactive cost behavior instead of guided governance. it lands hardest in onboarding, and on mature admins who use the dashboard episodically.

03 · the frame

reporting answers how things are. operating answers what to do.

reporting answers one question: how are things? operating answers four harder ones:

  • what should i do next?
  • which lever matters most right now?
  • if i act, what outcome should i expect?
  • are we safe from a governance perspective?

if the job is operating, then sequencing, prioritization, and decision scaffolding matter more than layout changes. so the session aligned on the job definition before debating solutions.

04 · the operating loop

orient → decide → act → learn

the hypothesis to pressure-test: the dashboard should support an explicit operating loop. today it may primarily support orient.

orient
the signals: participation, adoption, cost
decide
which lever matters most right now
act
a limited set of recommended actions
learn
what the action changed

admin usage is episodic, so each visit has to carry the whole loop: entropy reduction, clear prioritization, an obvious next action. ai's role, if any, is orchestration — ranking what matters, explaining why, prefilling actions, summarizing outcomes.

05 · programs as levers

programs should behave like levers, not inventory

  • tie programs to goals — not a flat inventory with transparent configuration and nothing ranked.
  • highlight one focus — goal-relative prioritization, so the most important program right now is obvious.
  • offer a limited set of recommended actions — a lever you can actually pull, not a list you maintain.

the open question: when participation dips, does the admin know which lever to pull, or is that typically prescribed from outside, by csms?

06 · cost as governance

cost should behave like governance

status
where cost stands, visible and finance-ready
explanation
why it moved, with expectation-setting around variance
safe intervention
a clear path to act that is safe to take

today cost comes up as exposure, with no structured path after it. the open question: when finance raises a cost concern, what path does the admin follow? the aim is guided cost governance instead of reactive cost behavior.

07 · the wedge

align on the job before debating solutions

the pre-read ends with the questions the session had to settle. the prototype is a working hypothesis to pressure-test against this framing, not a conclusion.

  • is the core problem correctly framed?
  • should the dashboard primarily operate, not just report?
  • is guided prioritization the right initial wedge?
  • which admin triggers matter most?
  • how disciplined should we be about phased validation?
  • what does success look like, from a leading and a lagging perspective?
what came out

an operating loop for admins — orient, decide, act, learn — programs ranked as levers, cost with a governance path.
